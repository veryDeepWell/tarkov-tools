# Tarkov Tools

Браузерный набор помощников для Escape from Tarkov. Текущая граница функциональности — R-3a «Скелетный ключ».

Каталог включает справочники экипировки, конструкторы сборок, калькуляторы бартеров и крафтов, квесты, карты, профиль ЧВК и мониторинг цен. Оценщик ключей принимает скриншот или текст и показывает найденные ключи, квесты и стоимость комплекта.

## Запуск

Нужен обычный HTTP-сервер, сборщик и серверная база не требуются:

```sh
python -m http.server 8080
```

Открой `http://localhost:8080/`. `index.html` перенаправляет в `tarkovtool-hub.html`. Для публикации подходит статический хостинг, например GitHub Pages. Открытие через `file://` ограничивает загрузку данных.

API-данные приходят из tarkov.dev. Профили, настройки и списки находятся в браузере; автоматического чтения прогресса из игры нет. Экспортируй данные перед очисткой хранилища сайта.

## Устройство

- `core/` — общие API, storage, профиль, навигация, предметный граф, расчёты и UI.
- `tools/` — HTML-страницы и их meta.
- `js/` — логика инструментов.
- `hub/` — каталог, мини-табы и настройки.
- `locales/` — переводы; `data/` — редакционные данные.

Каталог генерируется из HTML-meta: `python scripts/build-catalog.py`. Не редактируй `hub/catalog.js` вручную.

## Проверка без браузера

```sh
python scripts/build-catalog.py --check
python scripts/lint-architecture.py
python scripts/static-integrity-check.py
python scripts/ux-contract-check.py
node scripts/item-media-smoke-test.js
node scripts/release-audit-repro.cjs
```

Python и Node должны быть доступны в PATH. Дополнительные shell-контракты: `bash scripts/tool-contract-check.sh` и `bash scripts/domain-contract-check.sh`.

Регрессионные проверки используют фикстуры, без сетевых запросов и настоящего браузерного storage. Они не подтверждают точность OCR на скриншотах, визуальную вёрстку и актуальность данных игры.

## Headless-проверка в настоящем браузере

```sh
node scripts/browser-audit.cjs all
```

Нужны Playwright и Chromium либо Edge. Скрипт сам запускает HTTP-сервер на свободном локальном порту и отдельный headless-браузер с временными контекстами. Существующие вкладки и профиль браузера не используются. Буфер обмена подменяется только в тестовом контексте.

Если Playwright установлен вне проекта, задай `PLAYWRIGHT_MODULE_PATH` — путь к пакету. `PLAYWRIGHT_BROWSER_PATH` позволяет выбрать исполняемый файл браузера. Доступны этапы `smoke`, `exercise`, `flows`, `all`; `AUDIT_TOOLS=ammo,keys` ограничивает обход страниц, `AUDIT_CASES` фильтрует имена сценариев регулярным выражением. Результаты, скриншоты и снимки API находятся в `artifacts/browser-audit/` и не попадают в Git.

Первый запуск сохраняет реальные ответы API для обоих режимов и переводы. Последующие запуски используют этот снимок для повторяемости. Для нового снимка перемести содержимое `artifacts/browser-audit/snapshots/` в отдельную папку перед запуском. В массовом функциональном обходе внешние картинки заменяются заглушками, отдельно проверяется настоящее изображение предмета. OCR проверяется настоящим Tesseract на созданном тестовом изображении с текстом; качество игровых скриншотов этим не подтверждается.
