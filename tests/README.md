# Автотесты Tarkov Tools

Один запуск перед push: **`pnpm check`**. Он проверяет архитектуру, JS/HTML, локальные ссылки, domain/storage-контракты, прежние регрессии и тесты из этой папки. Любой неуспешный шаг возвращает ненулевой код.

## Установка и запуск

Нужны Node.js 22.13+, pnpm 11.25.0, Python 3 и Bash (в Windows — Git for Windows).

```sh
pnpm install --frozen-lockfile
pnpm hooks:install
pnpm check
```

Локально браузерные тесты выбирают установленный Edge и запускают его без окна, с отдельным профилем. На других системах используется Chromium Playwright; его нужно поставить один раз:

```sh
pnpm exec playwright install chromium
```

`PLAYWRIGHT_BROWSER_PATH` задаёт другой исполняемый файл браузера. `PYTHON` задаёт интерпретатор Python, если он не находится автоматически. Мышь, клавиатура, вкладки и профиль пользовательского браузера не используются.

- `pnpm test` — функциональные тесты Node + браузер.
- `pnpm test:browser` — OCR настоящего скрина, подбор престижа, иконки, перетаскивание и повороты.
- `pnpm test:unit` — сопоставление ключей и чистый алгоритм подбора/укладки.
- `pnpm check` — полный локальный и CI-барьер.

Установка hook выполняется отдельно в каждом клоне и не заменяет уже настроенный чужой `core.hooksPath`. После установки обычный `git push` запускает тот же `tests/check.cjs`, что и CI. Workflow `.github/workflows/architecture.yml` дополнительно сохраняет скриншоты при каждом запуске. Защита веток GitHub настраивается владельцем репозитория отдельно.

## Данные

- **`keyPic.png`** — исходный пользовательский скрин, не изменяется тестами.
- `fixtures/keyPic.expected.json` — ручная разметка его 48 заполненных ячеек, SHA-256 и минимальное покрытие. Сопоставленный ключ обязан совпасть с разметкой; случайная подстановка считается ошибкой. Повторы 108/214 и жилого модуля сохраняются. Обрезанные «Доступ» и неоднозначная «Времянка» остаются на ручное уточнение.
- `fixtures/catalog.json` — сокращённый реальный снимок tarkov.dev от 2026-11-01: весь каталог ключей, варианты жетонов, репрезентативные предметы, квесты и правила переноса каждого престижа. Цены фиксированы для воспроизводимости.
- `fixtures/icons/` — настоящие изображения предметов из assets.tarkov.dev, не нарисованные заменители.
- `fixtures/ocr-models/` — русская и английская модели `@tesseract.js-data`, `4.0.0_best_int`. Источник: [rus](https://cdn.jsdelivr.net/npm/@tesseract.js-data/rus/4.0.0_best_int/rus.traineddata.gz), [eng](https://cdn.jsdelivr.net/npm/@tesseract.js-data/eng/4.0.0_best_int/eng.traineddata.gz); [проект моделей](https://github.com/naptha/tessdata).

Тесты не скачивают данные и не меняют ожидаемый результат: API, изображения, worker, WASM и языковые модели обслуживаются локально. Неожиданный внешний запрос останавливает тест. При этом используется настоящий Tesseract в настоящем браузере; распознанный текст не подставляется фикстурой.

Текущее проверенное покрытие `keyPic.png`: **40/48 подписей**. Восьми оставшимся строкам требуется уточнение: пять подписей доступа, одна неоднозначная времянка и два кода с ошибками OCR. Это не обещание распознавать любой скрин с тем же качеством.

## Что предотвращают тесты

- Двойной подсчёт «найти» + «сдать»; начисление полной потребности каждой альтернативе.
- Автоматическое заполнение разновидностями жетонов без данных экземпляра.
- Подбор предметов вне серверного списка переноса, игнорирование исключений/уровня.
- Пересечения, выход за границы, изменение инвентаря при отмене или неудачном уменьшении сетки.
- Растягивание компактных кнопок глобальными стилями и перекрытие предметов.
- Пропавшие реальные иконки; строковый ID штатной оружейной сборки вместо разрешённого изображения/размеров.
- Ухудшение OCR на реальном скрине, неправильные номера комнат, потеря количества и ложные совпадения неоднозначных подписей.

Скриншоты и диагностика пишутся в **`artifacts/tests/`**, исключённый из Git. Это результаты проверки, а не автоматически обновляемые эталоны. Новые регрессии добавляй в файлы `*.test.cjs`; предметные данные — в `fixtures/` с указанием источника. При обновлении скрина сначала пересмотри ручную разметку, затем SHA-256. Тесты не должны обновлять ожидания сами.

`node tests/fetch-fixtures.cjs` — явная команда обслуживания локальных моделей/иконок из уже описанного каталога; обычный тестовый запуск её не выполняет.
