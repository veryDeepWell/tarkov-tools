# R3.19 — технический аудит и исправления

## Итог

Основная поломка табличных инструментов была вызвана рассинхронизацией HTML-страниц и общего движка таблиц. Исправление сделано на уровне общего контракта, без переписывания самих инструментов.

## Исправлено

### Общий движок таблиц

- Восстановлено подключение `core/tarkov-table-tool.js` на страницах инструментов, которые вызывают `TarkovTableTool.create(...)`, но больше не загружали этот файл.
- Восстановлены начальные элементы таблиц для страниц квестов и оптимизатора обмена. Движок кэширует `tbody`/`thead` при инициализации, поэтому создание таблицы только позднее не работало.
- Возвращены недостающие ID заголовков, на которые ссылаются JS-модули таблиц.
- Для крафтов исправлено несовпадение селектора заголовка и разметки: вместо неоднозначного `#thead` используется `#craftHead`.
- Исправлены неверные селекторы тела таблицы у аптечек (`#medBody`) и стимуляторов (`#stimBody`).
- В `core/tarkov-table-tool.js` сохранены существующие подписи столбцов по `data-k`/`data-s` при построении заголовка; если подпись не найдена, используется конфигурация столбца.
- Разделены два сценария загрузки: стандартный загрузчик движка и собственная загрузка инструмента. Для 12 инструментов с собственным `loadBtn.onclick` включён `autoLoad: false`, чтобы клик не запускал две конкурирующие загрузки и не перезаписывал статус/состояние кнопки.
- В `js/ammo.js` объявлена переменная `api`; прежнее присваивание необъявленному идентификатору в строгом режиме приводило к `ReferenceError`.

### Предметы для квестов

- Заменены несуществующие методы `TarkovStorage.load/save` на доступные интерфейсы `TarkovStorage.getJson/setJson` и методы профиля.
- Отметки выполнения теперь читаются из `TarkovProfile` и сохраняются через `setQuestItemDone`; очистка отметок использует `clearQuestItemDone`.
- Исправлена проверка `isItemDone` на фактически существующий `isQuestItemDone`.
- Возвращены типы целей `findQuestItem`, `giveQuestItem` и `plantQuestItem`, добавлены подписи на русском.
- Ключи отметок согласованы с форматом `taskId|objectiveId`.

### Автоматические проверки

`scripts/static-integrity-check.py` дополнен контрактной проверкой табличных страниц. Для каждого загруженного JS-модуля, использующего `TarkovTableTool.create(...)`, проверяются:

- подключение общего движка до скрипта инструмента;
- наличие указанных `thead` и `tbody`;
- соответствие ID ожидаемому HTML-элементу (`<thead>` или `<tbody>`);
- отключение стандартного автозагрузчика, если инструмент самостоятельно назначает `loadBtn.onclick`.

Проверяются все буквальные селекторы в модуле, а не только первое найденное вхождение.

## Ограничения проверки

- Браузерный smoke test не удалось завершить: установленный Chromium блокирует навигацию даже на локальный HTTP-сервер и `file://` с `ERR_BLOCKED_BY_ADMINISTRATOR`. Это ограничение среды, а не подтверждение работоспособности страницы.
- Внешний Tarkov API недоступен из среды проверки из-за ошибки DNS. Поэтому фактическая загрузка актуальных данных, полнота результатов и корректность отображения на live-данных требуют повторной проверки в обычном браузере с доступом к API.
- Автоматические проверки подтверждают синтаксис, локальные ссылки и согласованность контрактов; они не заменяют полноценного игрового и пользовательского тестирования всех 69 страниц.
