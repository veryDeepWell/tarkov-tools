# R3.21 — UX audit and change report

**Scope:** user-facing fixes and shared UI behavior; no wholesale architectural rewrite.

## What changed

### 1. Shared item names and images

- Added a single place for item display names and item image selection (`core/tarkov-item-media.js`).
- Weapon icons prefer `properties.defaultPreset` art when available. For example, a base weapon such as M4A1 should show the standard configured weapon instead of the bare receiver.
- `TarkovAPI.items()` populates an ID-indexed catalogue per game mode. Shared table cells use it to restore canonical names/icons when tool-specific view models contain only partial item data.
- Item cards, plates/armor view models, the Prestigeinator and the Stash Packer use the same media helper where available.

### 2. Global item inspector

- Added a floating `Инспектор: выкл/вкл` control on tool pages that use the shared shell.
- `Alt+I` toggles inspector mode. In that mode, clicking a supported item opens a compact item preview.
- Double-clicking a supported item opens the same preview without enabling inspector mode first.
- The preview includes the canonical name, item image, selected available stats and a link to the full Item Card. It preserves PvE/PvP mode, including `pvp-season`.
- Connected the common table name cells, grid items, and several item pickers/dialogs to the inspector.

### 3. Reported functional defects

- **NVG:** the results card was hidden by inline `display:none` and was not revealed after loading. It is now shown when data loading completes. Recognition also checks the API's night-vision property type, several common name patterns, and item types; the tool reports an empty result instead of silently leaving a hidden table.
- **Armor and plates:** compatibility windows now use the native dialog API (`showModal()` / `close()`) with a fallback. The previous `hidden=false` alone did not open a native `<dialog>`.
- **Item Card:** fixed references in the related-quest/craft/barter/hideout lists that used out-of-scope `href`/`iid` variables. The page now reads a requested mode from the URL for `pve`, `regular`, and `pvp-season`.

### 4. Prestigeinator

- Reworked the load/update flow inside a single closure, so event handlers can access the data and helpers they need.
- Starts with real API data and an empty board. Demonstration data is opt-in and visibly marked as demo; it is no longer silently presented as a live recommendation.
- Handles an unavailable item API as an explicit error. If tasks fail but items load, the tool can still work without quest prioritization and reports that limitation.
- The optimizer uses selectable focus modes (balanced, money, quests, Kappa, item density), quest-objective weighting, item dimensions, stack potential, and approximate value. It avoids packing containers inside the prestige window and limits candidates for responsive execution.
- Search suggestions show item icons and dimensions; manual placement and the automatic packing remain editable afterward.

### 5. Stash Packer / Укладка

- Replaced the opaque ASCII-style result with a visual slot grid; items show images, names and dimensions.
- Added search and an explicit multi-select list for cases, backpacks and rigs, plus Select All / Clear Selection actions. No Ctrl/⌘ modifier is required.
- Supports configurable board dimensions, orientation strategies, optional item rotation and a copy count capped at 20.
- Reports placed/unplaced items and occupied slots, validates board dimensions, and no longer truncates the candidate inventory to an arbitrary first 200 entries.

### 6. Regression protection

- Added `scripts/ux-contract-check.py` with 23 checks for the most fragile R3.21 integrations.
- Added `scripts/item-media-smoke-test.js` to verify default-preset weapon images, standard non-weapon image fallback, and non-mutating decoration.
- Wired both checks into `.github/workflows/architecture.yml`.
- Updated the R3.21 changelog entry and the obsolete Stash Packer multi-select label.

## Limitations and risks

- A full end-to-end browser session against the live Tarkov API was **not** completed in this environment. Chromium navigation is blocked by the environment's administrator policy and live API connectivity was not reliable in the previous verification attempt. Passing static and smoke tests does not prove every external API response or browser interaction is working in production.
- Night-vision classification is more tolerant but depends on the shape of the API item records. If the API changes its item-property schema, inspect the table's explicit empty-result status and the browser console.
- Prestige scoring is a heuristic, not an optimal proof: prices may be unavailable or stale, quest-objective data varies, and candidate packing may not be globally optimal.
- Stash Packer lays out the **outer dimensions** of selected containers on the user-configured board; the internal slot count is informational. It does not simulate arbitrary nesting of every container's own inventory.
- Inspector interactions are attached to supported item elements that expose item IDs. It cannot reliably identify arbitrary text/images on pages that do not expose a stable item ID.

## Baseline and installation note

This build was made from the previously delivered `tarkov-tools-R3.19-fixed.zip` snapshot, which is the latest project archive available in this conversation. Any code edits made only in the user's local copy after that archive was downloaded were not present for this audit and are not included here.

The **changed-files ZIP** contains only files changed or added relative to that baseline and is the preferred overlay for an existing project based on that snapshot. The **full ZIP** contains the complete project snapshot. Keep a backup before applying either package.
